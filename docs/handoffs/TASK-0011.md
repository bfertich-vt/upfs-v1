# TASK-0011 handoff

## Scope

This slice establishes the production-readiness boundary and a reproducible, synthetic release rehearsal. Existing in-memory services remain explicitly reference implementations; they are not silently promoted to production. `services/production-boundaries.mjs` requires injected PostgreSQL, transactional outbox, and durable checkpoint adapters and fails closed when any seam is absent or incomplete.

## Evidence and controls

- `scripts/release-rehearsal.mjs` verifies the adapter contract, absence of an in-memory production fallback, required delivery/security/testing/SOC 2 evidence documents, local-only configuration placeholders, and rollback/recovery language. It writes `artifacts/release-rehearsal-report.json` (ignored, synthetic-only).
- `services/production-boundaries.test.mjs` proves missing and incomplete durable adapters are rejected and injected implementations are preserved.
- No production deployment, provider credential, customer financial data, or SOC 2 attestation is claimed.
- PostgreSQL remains authoritative. Outbox append/claim/ack/fail and checkpoint load/save are explicit interfaces; implementations must provide transactionality, retry ownership, monotonic checkpoints, idempotency, and recovery before deployment.

## Rehearsal commands

```powershell
node --test services/*.test.mjs
node scripts/release-rehearsal.mjs
powershell -ExecutionPolicy Bypass -File scripts\validate.ps1
git diff --check
```

## Rollback and recovery

This change is documentation and boundary-contract only; rollback is a file-level revert. A production rollout must use an immutable release artifact, migration expand/contract rehearsal, canary health gates, outbox replay from the last durable checkpoint, projection reconciliation, and corrective-forward migration when rollback cannot safely reverse data changes. Failed writes must remain retryable and auditable; canonical facts and raw evidence are never deleted.

## Known limitations / follow-up

Concrete PostgreSQL repositories, migration runner, outbox worker, durable checkpoint store, managed secret provider, load/soak harness, and deployment orchestrator remain deployment work. The rehearsal intentionally does not pretend those external systems are available locally.
