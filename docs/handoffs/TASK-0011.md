# TASK-0011 handoff

## Scope

This slice establishes the production-readiness boundary and a reproducible, synthetic release rehearsal. Existing in-memory services remain explicitly reference implementations; they are not silently promoted to production. `services/production-boundaries.mjs` requires injected PostgreSQL, transactional outbox, and durable checkpoint adapters and fails closed when any seam is absent or incomplete.

## Evidence and controls

- `services/production-runtime.mjs` is the production composition root. It is exercised by `scripts/production-composition-check.mjs` and the rehearsal, requires injected PostgreSQL/outbox/checkpoint adapters and API service instances, and fails closed rather than constructing reference maps. Map-backed services remain test-only reference implementations.
- `scripts/release-rehearsal.mjs` executes 15 deterministic synthetic gates: composition/adapter contract, tenant isolation/BOLA/secret scan, checkpoint and outbox recovery, bounded load, migration dry-run/contract compatibility, and release artifact/configuration/rollback evidence. It writes `artifacts/release-rehearsal-report.json` (ignored, synthetic-only).
- `services/production-boundaries.test.mjs` and `scripts/release-rehearsal.test.mjs` prove missing and incomplete durable adapters are rejected, composition is invoked, and every rehearsal gate passes.
- No production deployment, provider credential, customer financial data, or SOC 2 attestation is claimed.
- PostgreSQL remains authoritative. Outbox append/claim/ack/fail and checkpoint load/save are explicit interfaces; implementations must provide transactionality, retry ownership, monotonic checkpoints, idempotency, and recovery before deployment.

## Rehearsal commands

```powershell
powershell -ExecutionPolicy Bypass -File scripts\validate.ps1
git diff --check
```

## Rollback and recovery

This change is documentation and boundary-contract only; rollback is a file-level revert. A production rollout must use an immutable release artifact, migration expand/contract rehearsal, canary health gates, outbox replay from the last durable checkpoint, projection reconciliation, and corrective-forward migration when rollback cannot safely reverse data changes. Failed writes must remain retryable and auditable; canonical facts and raw evidence are never deleted.

## Known limitations / follow-up

Concrete PostgreSQL repositories, migration runner, outbox worker, durable checkpoint store, managed secret provider, load/soak harness, and deployment orchestrator remain deployment work. The rehearsal intentionally does not pretend those external systems are available locally.

Exact unmet prerequisites before production authorization: provision and security-review PostgreSQL repositories with transaction/RLS tests; deploy a transactional outbox worker with retry/claim/ack/fail metrics; provision a durable monotonic checkpoint store and recovery drill; run the real migration expand/contract rehearsal against a disposable PostgreSQL target; configure an approved managed secret provider; execute an environment-sized load/soak test; and obtain deployment/change approval. Rollback remains immutable-artifact revert plus corrective-forward migration when data changes cannot be reversed; replay outbox events from the last durable checkpoint and reconcile projections after recovery.
