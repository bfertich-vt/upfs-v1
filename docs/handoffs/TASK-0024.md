# TASK-0024 Handoff — Admin approval-gated operation workflows

## Scope

The admin console now exposes API-backed administrative operation records and bounded controls for creating synthetic dry runs, independent approval, execution, and rollback. Each mutating request carries an explicit idempotency key; creation requires tenant/environment scope and reason. Approval and rollback collect human context and explicitly submit dual-control/evidence fields.

## Safety boundaries

Execution controls are disabled unless the operation explicitly reports both managed credentials and external approval. The UI always creates dry-run operations and displays an explicit fail-closed explanation. No database, provider, credential, or financial payload is accessed by the console.

## Evidence

- `node --test apps/admin-console/admin-console.test.mjs`: 7 passed
- API route tests cover list/create/approve/execute/rollback paths and idempotency headers.
- Synthetic UI test verifies operation loading and production execution disabled when managed credentials/external approval are unavailable.

## Follow-up

The service remains the authority for actor authorization, policy, dual control, audit, rollback evidence, and managed credential checks. This task adds only the contract-bound interaction surface; no task queue status is changed here.
