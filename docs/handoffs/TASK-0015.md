# TASK-0015 handoff

- Scope: immutable release manifest, SBOM/provenance references, managed configuration gates, canary/reconciliation checks, and rollback evidence.
- Implementation: `scripts/task-0015-release-evidence.mjs` hashes release inputs and migration content, emits a deterministic release manifest with HMAC signature metadata, and executes synthetic canary, reconciliation, and corrective-forward gates. `scripts/task-0015-release-evidence.test.mjs` verifies pass and fail-closed production configuration paths.
- Evidence: `artifacts/task-0015-release-report.json` and `artifacts/upfs-release-manifest.json` are generated (ignored artifacts). The rehearsal is synthetic-only; no deployment, external approval, real credential, or customer data is used.
- Configuration: pilot/production requires `UPFS_MANAGED_SECRET_REF` and `UPFS_CONFIG_REF`; checked-in `.env.example` remains local-only. Signing key is only read from a managed runtime secret; absent key is explicitly labeled `synthetic-test-only`.
- Deployment/rollback: canary health and post-deploy reconciliation are prerequisites. Rollback requires explicit external approval and follows corrective-forward migration policy; no release script mutates external systems.
- Tests and commands: `node --test scripts/task-0015-release-evidence.test.mjs`, full `node --test services/*.test.mjs scripts/*.test.mjs`, `scripts/validate.ps1`, and `git diff --check`.
- Known limitations: native cryptographic signing, hosted SBOM attestation, live canary, and PostgreSQL-backed evidence require external controlled infrastructure and approval; this task does not claim deployment or certification.
