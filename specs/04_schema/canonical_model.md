# Canonical model

## Primitive record families

Party, identity, institution, product, account, balance, transaction, merchant, recurring series, transfer, income/payroll, liability, security, holding, investment transaction, document, communication, tax object, benefit, insurance, real asset, business, consent, authorization, source observation, assertion, conflict, correction, evidence, relationship, financial state.

## Required metadata

Every canonical record includes stable ID, tenant/environment, schema version, lifecycle state, valid-time interval, system-time interval, source observations, evidence references, confidence, provenance/transformation chain, data classification, created/updated actors, and version.

## Transaction taxonomy

Preserve provider categories; map them to a governed UPFS hierarchy with domain, family, class, subclass, intent, cash-flow role, tax relevance, recurrence, merchant confidence, and user override. Overrides are assertions with evidence and history, never destructive replacements.

## Enrichment

Email, receipt, document, merchant, location, device, payroll, and statement signals require consent, minimal collection, source hierarchy, purpose limitation, retention, malware/content scanning, prompt-injection classification, and evidence links.
